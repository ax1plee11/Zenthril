## 2. CRITICAL

### CRY-101 — Клиент и Go выводят криптографически несовместимый материал
- **Component:** E2EE / Double Ratchet
- **File:** `client/src/crypto/ratchet.ts:21-32`, `backend/internal/crypto/ratchet.go:291-304`
- **Problem:** цепной ратчет использует разные salt и info и разную раскладку сегментов. Инициализация сессии различается сильнее: у клиента IKM — конкатенация DH-значений, у Go — единый `sharedSecret`.
- **Root cause:** две реализации развивались независимо; нет общего владельца схемы и нет кросс-реализационных test vectors.
- **Impact:** сквозное шифрование не может работать между реализациями. Заявлять соответствие Signal нельзя.
- **Proposed fix:** выбрать эталонную схему (рекомендуется Go — сервер хранит состояние сессий), привести клиент к ней, добавить кросс-реализационный вектор, исполняемый в обоих языках.
- **Test required:** единый вектор входа → один и тот же ключ/IV в Go и TypeScript; round-trip через WebCrypto.
- **Risk:** HIGH — изменение криптографического поведения. **Требует явного разрешения владельца.**
- **Dependencies:** нет

> Изменение затрагивает протокол. По правилам проекта не выполняется без отдельного решения.

### PROD-205 — Аватары не сохраняются на сервере
- **File:** `client/src/components/ProfileModal.tsx:92-97`
- **Problem:** файл читается в base64 и хранится только локально; API загрузки отсутствует. Лимит 5 МБ проверяется только на клиенте, что даёт ~6,7 МБ base64 и риск переполнения квоты localStorage
- **Impact:** аватар не синхронизируется между устройствами; выбор крупного файла, вероятно, приведёт к `QuotaExceededError` без обработки
- **Fix:** либо реализовать endpoint загрузки с серверной валидацией размера, либо убрать UI
- **Risk:** LOW

## 8. Что невозможно доказать внутри проекта

| Пункт | Почему |
|---|---|
| Внешняя криптографическая экспертиза | требует независимого аудита; не может быть заменена внутренним тестом |
