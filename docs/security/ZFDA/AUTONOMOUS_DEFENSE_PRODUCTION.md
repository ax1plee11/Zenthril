# ZFDA AUTONOMOUS_DEFENSE_PRODUCTION — Автономная защита: Production Readiness

## Обзор

Автономная защита (Autonomous Defense) реализована как набор пяти двигателей:
- ThreatDetector — обнаружение угроз
- RiskEngine — оценка уровня риска
- PolicyEngine — принятие решений по политикам
- ResponseEngine — выполнение защитных действий
- RecoveryEngine — безопасное восстановление

Все двигатели объединены в `GlobalAutonomousDefense` 싱글тон и подключены к реальным событиям приложения.

## Интеграция с реальными событиями

| Событие | Функция | Тип угрозы | Риск | Действия |
|---------|---------|------------|------|----------|
| Неудачные попытки входа | `RecordAuthenticationFailure` | brute_force | High | Block session, Limit activity |
| Неудачные попытки TOTP | `RecordTOTPFailure` | credential_stuffing | High | Require MFA, Limit activity |
| Повторное использование токена | `RecordTokenReuse` | token_reuse | Critical | Revoke token, Block session |
| WebSocket флуд | `RecordWebSocketFlood` | websocket_flood | High | Block session, Limit activity |
| Аномальная сессия | `RecordAnomalousSession` | anomalous_session | Medium | Require MFA, Limit activity |
| Превышение rate limit | `RecordRateLimitExceeded` | rate_limit_exceeded | High | Limit activity, Block session |
| Подозрительное устройство | `RecordSuspiciousDevice` | suspicious_device | High | Block session, Require MFA* |

\* Требует ручного одобрения

## Проверка при отказе компонентов

| Scenario | Поведение | Безопасность |
|----------|-----------|--------------|
| Redis недоступен | Автономная защита не может записывать события | Действия не выполняются, логируются через slog |
| PostgreSQL недоступен | Автономная защита продолжает работать (in-memory) | Риск накопления в памяти, события теряются при перезапуске |
| WebSocket перегрузка | Отдельные лимиты на соединение и пользователя | Отдельная защита от флуда |
| Много auth failures | RiskEngine накапливает очки, риск растет | Блокировка сессии после превышения порога |
| Повторные события | Каждое событие обрабатывается независимо | Риск накапливается, действия усиливаются |
| Конфликтующие политики | Первое совпадающее правило применяется | Детерминистичное поведение |
| Перезапуск backend | Состояние в памяти теряется | Нужно внедрить персистентное состояние для production |

## Ограничения полномочий

| Ограничение | Реализация |
|-------------|------------|
| Нет автоматического уничтожения данных | Нет действий удаления в ResponseEngine |
| Нет массовой блокировки пользователей | Действия только на уровне пользователя/сессии |
| Нет бесконечных циклов реагирования | Одно выполнение на событие, нет рекурсии |
| Нет отключения критических компонентов | SafeMode требует ручного одобрения |
| Нет подделки событий через клиент API | События генерируются только серверной стороной |
| E2EE контент не в анализе | Только метаданные (userID, IP, deviceID) |

## Аудитный трей

Все защитные действия логируются через `SecurityAuditLogger`:
- Тип действия, цель, длительность, уровень риска, причина
- Кто/что инициировал действие (автоматическое vs ручное)
- Время выполнения и время истечения
- Все отмены действий логируются

## Пропуски для production

| Элемент | Статус | Требуется для production |
|---------|--------|-------------------------|
| ResponseExecutor с реальными действиями | ❌ Default logger only | Настроить реальный executor (блокировка сессий, отзыв токенов) |
| Персистентное состояние рисков | ❌ In-memory only | Сохранение в Redis/PostgreSQL |
| Rate limiting на действия | ❌ Нет глобального лимита | Добавить защиту от массовых блокировок |
| Интеграция с реальными событиями | ⚠️ Частично | Подключить ко всем endpoint'ам |
| Тесты с реальной инфраструктурой | ❌ Нет | Интеграционные тесты с Redis/PostgreSQL |
| Мониторинг автономной защиты | ❌ Нет | Добавить метрики и алерты |

## Требования к production

1. Настроить `ResponseExecutor` с реальными действиями (блокировка сессий, отзыв токенов, изоляция устройств)
2. Добавить персистентное состояние для RiskEngine (Redis/PostgreSQL)
3. Добавить глобальный rate limiting на защитные действия
4. Подключить Autonomous Defense ко всем критическим endpoint'ам
5. Добавить метрики и алерты для автономной защиты
6. Провести интеграционные тесты с реальной инфраструктурой
7. Создать runbook для операторов безопасности
