# ZFDA TRUST_BOUNDARIES — Границы доверия Zenthril

## Определенные границы доверия

### TB-1: Клиент → Backend HTTP API

**Направление:** Tauri клиент → Go backend (порт 8080)

**Механизм доверия:**
- JWT access токен (HS256, 15 мин TTL) в заголовке `Authorization: Bearer`
- CORS allowlist (точные origin, без wildcard)
- Security headers (CSP, HSTS, frame protection, MIME sniffing, Referrer Policy, Permissions Policy)

**Не доверяется:** Клиент не доверяется автоматически. Каждый запрос валидируется на сервере.

**Критичность:** Высокая — компрометация JWT_SECRET дает полный контроль.

### TB-2: Клиент → WebSocket шлюз

**Направление:** Tauri клиент → Go WebSocket (порт 8080 /ws)

**Механизм доверия:**
- Одноразовый WebSocket тикет (TTL 2 мин, GETDEL)
- Strict Origin allowlist (fail-closed при отсутствии конфигурации)
- Проверка глобальной блокировки аккаунта

**Не доверяется:** Установленное WebSocket соединение не считается доверенным само по себе. Каждое сообщение валидируется.

**Критичность:** Высокая — реалтайм доступ к сообщениям и сигнализации.

### TB-3: Backend → PostgreSQL

**Направление:** Go backend → PostgreSQL 16 (внутри Docker сети, порт не publikuje)

**Механизм доверия:**
- Параметризованные запросы (pgx, без конкатенации строк)
- Пользователь БД с ограниченными правами
- sslmode=disable внутри доверенной Docker сети

**Не доверяется:** База данных не доступна всем компонентам напрямую. Только backend имеет прямой доступ.

**Критичность:** Критическая — содержит все пользовательские данные и ключи устройств.

### TB-4: Backend → Redis

**Направление:** Go backend → Redis 7 (внутри Docker сети, порт не publikuje)

**Механизм доверия:**
- Изоляция в Docker сети
- Отдельные пространства ключей для разных целей (refresh, blacklist, tickets, rate limiting)

**Критичность:** Высокая — хранение сессий и токенов.

### TB-5: Клиент → Локальное хранилище ключей

**Направление:** Tauri клиент → OS keychain (Windows Credential Manager / macOS Keychain / Linux Secret Service)

**Механизм доверия:**
- Приватные E2EE ключи не покидают клиентское устройство
- legacy `tauri-plugin-store` мигрируется и удаляется
- Проверка соответствия userId при загрузке бандлов ключей

**Не доверяется:** Компрометация локальной машины компрометирует ключи на этом устройстве.

### TB-6: Federation boundary (будущая)

**Направление:** Узел Zenthril → удаленный узел

**Механизм доверия:** Отключена по умолчанию (`FEDERATION_ENABLED=false`), fail-closed, требует `FEDERATION_TOKEN`

**Критичность:** Планируемая, не Produktions-готовая.

### TB-7: Object storage / media boundary (будущая)

**Направление:** Backend → объектное хранилище

**Статус:** Не реализовано, scaffolds только.

## Принцип Zero Trust

Никакой компонент не доверяется по умолчанию. Каждый запрос между границами доверия проходит независимую проверку аутентификации и авторизации.

## Точки отказа

Одна скомпрометированная граница доверия не должна приводить к компрометации всей системы. JWT_SECRET, Redis и PostgreSQL являются общими точками отказа и требуют усиленной защиты.
