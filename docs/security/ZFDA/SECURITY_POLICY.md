# ZFDA SECURITY_POLICY — Политика безопасности Zenthril

## Общие принципы

1. Защита встроена в архитектуру с самого начала (Secure by Default).
2. Каждый компонент имеет определенную модель угроз.
3. Между компонентами существуют четкие границы доверия (Zero Trust).
4. Все критические операции проходят независимые проверки на серверной стороне.
5. Компрометация одного уровня не открывает доступ ко всей системы (Defense in Depth).
6. Подозрительная активность обнаруживается и обрабатывается.
7. Защитные механизмы проверяются автоматическими и независимыми тестами.
8. Пользовательские данные и E2EE защищены даже при компрометации сервера.
9. Система способна безопасно ограничивать угрозу и восстанавливаться после инцидента.

## Управление доступом

- Аутентификация: пароль + Argon2id хеширование, JWT HS256 access токены.
- Авторизация: RBAC v2, проверка доступа к каналам и гильдиям на сервере.
- Административный доступ: только через `ADMIN_USER_IDS` конфигурацию, не выдается через API ролей.
- Сессии:限量 активных устройств (10 на пользователя), отзыв устройств, глобальная блокировка.

## Управление токенами

- Access токены: короткоживущие (15 мин), черный список при выходе.
- Refresh токены: отслеживаются на стороне сервера, ротация через GETDEL, детекция replay.
- WebSocket тикеты: одноразовые, TTL 2 мин.
- Логи не содержат паролей, токенов, приватных ключей или содержимого E2EE-сообщений.

## Криптография

- Используются проверенные стандарты: X25519, HKDF-SHA256, AES-256-GCM, Ed25519.
- Собственные криптографические алгоритмы запрещены.
- Сервер не получает возможность расшифровывать пользовательские сообщения (E2EE).
- Приватные ключи хранятся на клиенте в OS keychain.

## Инциденты

- Подозрительные сессии могут быть заблокированы временно.
- Компрометированные токены отзываются.
- Компрометированные устройства отзываются.
- Автоматические действия имеют ограничения, аудит и механизм отмены.
- Автоматическое уничтожение данных запрещено без проверок и ручного контроля.

## Регламент

- Все изменения проходят Code Review и соответствующие тесты.
- Миграции сохраняют совместимость и возможность безопасного отката.
- Секреты не хранятся в исходном коде.
- Нет скрытых каналов передачи данных и телеметрии.

Источники: NIST SP 800-53, OWASP ASVS, ISO/IEC 27001. Проверено: 2026-10-30.
