# ZFDA 1.3 — Data Protection (Защита данных)

## 1. Классификация данных

| Категория | Примеры | Уровень защиты | Шифрование в передаче | Шифрование при хранении |
|-----------|---------|----------------|----------------------|------------------------|
| Публичные | Информация о гильдиях (имя, описание), публичные профили | Низкий | HTTPS/WSS | Нет |
| Пользовательские | Имена пользователей, аватары, настройки | Средний | HTTPS/WSS | Нет (application-level не требуется) |
| Конфиденциальные | Список контактов, история сообщений (метаданные), членства в гильдиях | Высокий | HTTPS/WSS | Нет (только E2EE для содержимого) |
| Аутентификационные | Пароли (хэш), токены сессий, refresh токены, TOTP секреты | Критический | HTTPS/WSS | Argon2id (пароли), AES-256-GCM (TOTP), Redis с аутентификацией |
| Криптографические | E2EE приватные ключи, signed prekeys, one-time prekeys, корневые ключи сессий | Критический | Никогда не передаются на сервер | OS keyring (клиент), никогда на сервере |
| Системные | Логи, метрики, конфигурация инфраструктуры | Средний | Внутри внутренней сети | Нет (логи не должны содержать секреты) |
| Резервные копии | Дампы БД, конфигурации, критические секреты | Критический | TLS при передаче | AES-256-GCM (зашифрованные бэкапы) |

## 2. Шифрование в передаче (Encryption in Transit)

| Соединение | Протокол | Статус |
|------------|----------|--------|
| Клиент ↔ Бэкенд (HTTP) | HTTPS (TLS 1.2+) | Partially (не enforced в dev) |
| Клиент ↔ Бэкенд (WebSocket) | WSS (TLS 1.2+) | Partially (не enforced в dev) |
| Бэкенд ↔ PostgreSQL | TCP (внутри Docker сети) | Partially (`sslmode=disable`, требует донастройки для production) |
| Бэкенд ↔ Redis | TCP (внутри Docker сети) | Partially (требует TLS для production) |
| Бэкенд ↔ Event bus (Kafka) | TLS (production) | Not Verified (EVENT_BUS_DRIVER=memory в dev) |
| Бэкенд ↔ Federation узлы | mTLS (alpha) | Not Verified (федерация отключена) |

## 3. Шифрование при хранении (Encryption at Rest)

| Компонент | Механизм | Статус |
|-----------|----------|--------|
| PostgreSQL данные | Дисковое шифрование на уровне ОС/облака | Not Verified (требует доступа к серверу) |
| Redis данные | Дисковое шифрование на уровне ОС/облака | Not Verified |
| Файловые вложения | Шифрование на стороне клиента (E2EE) | Partially (кейш в браузере/Tauri) |
| Логи | Не должны содержать секреты | Verified (логи не содержат секретов по коду) |

**Примечание:** Шифрование диска не защищает данные от компрометации работающего приложения (процесс имеет доступ к расшифрованным данным).

## 4. Application-Level Encryption

| Данные | Механизм | Ключ | Статус |
|--------|----------|------|--------|
| Пароли пользователей | Argon2id | Соль на пользователя | Verified |
| TOTP секреты | AES-256-GCM | TOTP_ENCRYPTION_KEY | Partially (ключ в .env) |
| Refresh токены | Хэширование + шифрование в Redis | Redis аутентификация | Verified |
| Access токены | JWT (HS256 подпись) | JWT_SECRET | Partially (ключ в .env) |
| E2EE ключи пользователей | OS keyring (Tauri), Memory (Web) | На устройстве пользователя | Partially (alpha) |

## 5. End-to-End Encryption (E2EE)

**Принцип:** Сервер НЕ имеет доступа к приватным ключам пользователей и не может расшифровывать сообщения.

| Компонент | Реализация | Статус |
|-----------|------------|--------|
| X25519 key agreement | Backend + Client | Verified |
| HKDF-SHA256 derivation | Backend + Client | Verified |
| AES-256-GCM message encryption | Client | Verified |
| Protocol-v2 envelope | Backend + Client | Verified |
| X3DH bootstrap | Client (backend не инициирует) | Partially |
| Double Ratchet | Backend + Client | Partially (alpha) |
| Safety numbers | Client | Partially |
| Group Sender Keys | Client (max 10 устройств) | Partially |
| Device verification | Safety numbers + QR | Partially |
| Key recovery | Не реализовано | Not Applicable (roadmap) |

**Ограничения:**
- E2EE не является Signal-grade (нет внешнего аудита)
- Backend не может инициировать X3DH сессии (private keys never leave client)
- Нет внешнего криптографического аудита

## 6. Защита метаданных

| Метаданные | Видимость серверу | Защита |
|------------|-------------------|--------|
| Отправитель/получатель | Да | Нет (необходимо для маршрутизации) |
| Канал/гильдия | Да | Нет |
| Время сообщения | Да | Нет |
| Размер шифротекста | Да | Нет (возможна анализ трафика) |
| IP адрес | Да | Rate limiting, trusted proxy |

**Рекомендация:** Документировать утечку метаданных как 알려진 риск. Рассмотреть padding и батчинг для будущих версий.

## 7. Удаление данных

| Данные | Механизм удаления | Статус |
|--------|-------------------|--------|
| Удаление пользователя | Каскадное удаление из БД | Verified (логика на уровне приложения) |
| Удаление сообщения | Мягкое удаление / физическое | Verified |
| Отзыв refresh токена | `GETDEL` из Redis | Verified |
| Чёрный список access токена | В Redis до истечения TTL | Verified |
| Отзыв устройства | Удаление ключевой связки | Verified |

## 8. Доступ к резервным копиям

| Роль | Доступ | Механизм |
|------|--------|----------|
| Администратор инфраструктуры | Полное восстановление | Ключи доступа к secret manager |
| Разработчик | Нет доступа к production бэкапам | — |
| Система мониторинга | Нет | — |

### Статус: Partially Verified (классификация и механизмы описаны, полная верификация требует production доступа)
