# ZFDA 1.3 — Этап E: Backup & Disaster Recovery (Резервное копирование и аварийное восстановление)

## 1. Стратегия резервного копирования

### PostgreSQL

| Параметр | Значение |
|----------|----------|
| Тип бэкапа | Логический дамп (`pg_dump`) + физический (WAL archiving) |
| Частота полных бэкапов | Ежедневно (03:00 UTC) |
| Частота инкрементальных | Каждые 30 минут (WAL archiving) |
| Retention | 30 дней полных, 7 дней WAL |
| Шифрование | AES-256-GCM перед отправкой offsite |
| Место хранения | Offsite (разный регион/провайдер) |

### Redis

| Параметр | Значение |
|----------|----------|
| Тип бэкапа | RDB снимки + AOF лог |
| Частота | Каждые 4 часа (RDB), непрерывно (AOF) |
| Retention | 7 дней |
| Шифрование | AES-256-GCM |
| Место хранения | Offsite |

### Конфигурации

| Параметр | Значение |
|----------|----------|
| Что бэкапить | docker-compose.yml, .env.example, конфиги Nginx/Caddy, скрипты развёртывания |
| Частота | При каждом изменении (в Git) |
| Место хранения | Git репозиторий |

### Криптографические ключи

| Параметр | Значение |
|----------|----------|
| Что бэкапить | JWT_SECRET, TOTP_ENCRYPTION_KEY, E2EE приватные ключи (только пользовательские устройства) |
| Частота | При изменении |
| Место хранения | Secret Manager с резервной копией в зашифрованном виде offsite |

## 2. RPO и RTO

| Компонент | RPO (목ель) | RTO (цель) |
|-----------|-------------|------------|
| PostgreSQL | 30 минут (WAL archiving) | 2 часа |
| Redis | 4 часа (RDB) | 1 час |
| Конфигурации | 0 (в Git) | 30 минут |
| Секреты | 0 (в Secret Manager) | 1 час |

## 3. Процедура восстановления

### Восстановление PostgreSQL

```bash
# 1. Развернуть новый экземпляр PostgreSQL
docker run --name zenthril-postgres-restore -e POSTGRES_PASSWORD=<secret> -d postgres:16-alpine

# 2. Расшифровать бэкап
gpg --decrypt backup-2026-11-02.sql.gpg > backup-2026-11-02.sql

# 3. Восстановить дамп
psql -U zenthril -d zenthril -f backup-2026-11-02.sql

# 4. Применить миграции (если необходимо)
psql -U zenthril -d zenthril -f ./backend/migrations/00*.sql
```

### Восстановление Redis

```bash
# 1. Развернуть Redis
docker run --name zenthril-redis-restore -d redis:7-alpine

# 2. Скопировать RDB/AOF файлы
docker cp dump.rdb zenthril-redis-restore:/data/
docker cp appendonly.aof zenthril-redis-restore:/data/

# 3. Перезапустить Redis
docker restart zenthril-redis-restore
```

### Восстановление приложения

```bash
# 1. Получить конфигурацию из Git
git clone https://github.com/ax1plee11/Zenthril.git

# 2. Настроить секреты из Secret Manager
# 3. Собрать и запустить Docker контейнеры
docker compose up -d

# 4. Проверить health endpoints
curl -H "Authorization: Bearer $OPERATIONAL_TOKEN" http://localhost:8081/livez
```
