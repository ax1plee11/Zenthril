# План экспериментов для магистерской работы

## Цель исследования

Оценить производительность, масштабируемость и безопасность децентрализованного мессенджера Zenthril с E2EE и федеративной архитектурой.

## Эксперименты

### 1. Производительность шифрования (AES-256-GCM)

**Цель:** Измерить накладные расходы E2EE шифрования

**Метрики:**
- Время шифрования (мс)
- Время дешифрования (мс)
- Операций в секунду
- Потребление CPU/памяти

**Сценарии:**
- Короткие сообщения (100 байт)
- Средние сообщения (1 KB)
- Большие сообщения (10 KB)
- Очень большие (100 KB)

**Ожидаемые результаты:**
- Шифрование < 1ms для сообщений до 10KB
- Линейная зависимость от размера
- Минимальное потребление памяти

### 2. Масштабируемость WebSocket

**Цель:** Определить максимальное количество одновременных подключений

**Метрики:**
- Активные подключения
- Задержка доставки (P50, P95, P99)
- Пропускная способность (msg/sec)
- Потребление ресурсов

**Сценарии:**
- 10 пользователей
- 50 пользователей
- 100 пользователей
- 500 пользователей
- 1000 пользователей
- 5000 пользователей (стресс-тест)

**Ожидаемые результаты:**
- 1000+ одновременных пользователей
- P95 < 200ms при 500 пользователях
- Линейное масштабирование

### 3. Производительность базы данных

**Цель:** Оптимизировать запросы к PostgreSQL

**Метрики:**
- Время INSERT/SELECT/UPDATE
- Влияние индексов
- Параллельные запросы
- Размер БД

**Сценарии:**
- Вставка сообщений
- Выборка истории
- Обновление статусов
- Транзакции

**Ожидаемые результаты:**
- INSERT < 5ms
- SELECT < 10ms
- Индексы ускоряют в 10+ раз

### 4. Нагрузочное тестирование

**Цель:** Проверить стабильность под нагрузкой

**Метрики:**
- Процент ошибок
- Время отклика
- Потребление ресурсов
- Утечки памяти

**Сценарии:**
- Smoke test (1 пользователь, 1 минута)
- Load test (100 пользователей, 5 минут)
- Stress test (500 пользователей, 10 минут)
- Spike test (0→1000→0 пользователей)
- Soak test (200 пользователей, 2 часа)

**Ожидаемые результаты:**
- Ошибок < 1%
- Стабильная работа 2+ часа
- Нет утечек памяти

### 5. Сравнение с аналогами

**Цель:** Сравнить с существующими решениями

**Сравниваемые системы:**
- Signal Protocol
- Matrix Synapse
- Telegram MTProto
- XMPP + OMEMO

**Метрики:**
- Задержка сообщений
- Потребление ресурсов
- Масштабируемость
- Безопасность

**Ожидаемые результаты:**
- Сопоставимая производительность
- Лучшая масштабируемость (федерация)
- Аналогичная безопасность

### Риск 3: Утечки памяти

**Митигация:** Развёртывание аналогов, публичные бенчмарки
