# Нагрузочное тестирование Zenthril

Инструменты и скрипты для нагрузочного тестирования мессенджера.

## 🎯 Цели тестирования

1. **Производительность WebSocket** - сколько одновременных подключений выдерживает сервер
2. **Задержка сообщений** - P50, P95, P99 латентность доставки
3. **Пропускная способность** - сообщений в секунду
4. **Стабильность под нагрузкой** - поведение при 1000+ пользователях
5. **Потребление ресурсов** - CPU, память, сеть

## 📊 Инструменты

### k6 (рекомендуется)

Современный инструмент для нагрузочного тестирования.

**Установка:**
```bash
# Windows (Chocolatey)
choco install k6

# macOS
brew install k6

# Linux
sudo gpg -k
sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D69
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt-get update
sudo apt-get install k6
```

**Запуск теста:**
```bash
# Базовый тест
k6 run k6_load_test.js

# С кастомными параметрами
k6 run --vus 100 --duration 30s k6_load_test.js

# С указанием URL сервера
k6 run -e BASE_URL=http://your-server:8080 -e WS_URL=ws://your-server:8080 k6_load_test.js

# Сохранение результатов
k6 run --out json=results.json k6_load_test.js
```

## 🧪 Сценарии тестирования

### 1. Smoke Test (проверка работоспособности)
```bash
k6 run --vus 1 --duration 1m k6_load_test.js
```
- 1 виртуальный пользователь
- 1 минута
- Проверка базовой функциональности

### 2. Load Test (обычная нагрузка)
```bash
k6 run --vus 100 --duration 5m k6_load_test.js
```
- 100 одновременных пользователей
- 5 минут
- Симуляция обычной нагрузки

### 3. Stress Test (стресс-тест)
```bash
k6 run --vus 500 --duration 10m k6_load_test.js
```
- 500 одновременных пользователей
- 10 минут
- Поиск пределов системы

### 4. Spike Test (пиковая нагрузка)
```bash
k6 run --stage 0s:0,10s:1000,1m:1000,10s:0 k6_load_test.js
```
- Резкий скачок до 1000 пользователей
- Проверка поведения при внезапной нагрузке

### 5. Soak Test (длительный тест)
```bash
k6 run --vus 200 --duration 2h k6_load_test.js
```
- 200 пользователей
- 2 часа
- Проверка утечек памяти и стабильности

## 📈 Метрики для анализа

### Ключевые показатели:

1. **HTTP метрики:**
   - `http_req_duration` - время ответа (P50, P95, P99)
   - `http_req_failed` - процент ошибок
   - `http_reqs` - количество запросов в секунду

2. **WebSocket метрики:**
   - `ws_connections` - количество подключений
   - `message_latency` - задержка доставки сообщений
   - `messages_sent` - отправлено сообщений
   - `messages_received` - получено сообщений

3. **Системные метрики:**
   - CPU usage
   - Memory usage
   - Network I/O
   - Database connections

## 📊 Анализ результатов

### Пороговые значения (thresholds):

```javascript
thresholds: {
  http_req_duration: ['p(95)<500', 'p(99)<1000'], // 95% < 500ms, 99% < 1s
  http_req_failed: ['rate<0.01'],                  // < 1% ошибок
  message_latency: ['p(95)<200', 'p(99)<500'],    // Задержка сообщений
}
```

### Интерпретация:

- ✅ **Отлично**: P95 < 200ms, P99 < 500ms, ошибок < 0.1%
- ⚠️ **Приемлемо**: P95 < 500ms, P99 < 1000ms, ошибок < 1%
- ❌ **Плохо**: P95 > 1000ms, P99 > 2000ms, ошибок > 5%

## 🔍 Мониторинг во время теста

### 1. Метрики сервера
```bash
# Открыть в браузере
http://localhost:8080/metrics
```

### 2. Системные ресурсы
```bash
# Linux/macOS
htop

# Windows
Task Manager или:
Get-Process | Sort-Object CPU -Descending | Select-Object -First 10
```

### 3. База данных
```sql
-- Активные подключения
SELECT count(*) FROM pg_stat_activity;

-- Медленные запросы
SELECT pid, now() - query_start as duration, query 
FROM pg_stat_activity 
WHERE state = 'active' 
ORDER BY duration DESC;
```
