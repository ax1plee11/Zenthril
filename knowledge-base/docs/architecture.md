# Architecture — границы сервисов KB Gateway

Компонент | Где хранятся данные | Как работает
---|---|---
PostgreSQL | Аккаунты, сайты, права, ScanRun, Finding, доказательства | Главная операционная БД; в Finding фиксируется kb_release_id и rule_revision_key
Neo4j | CWE, CVE, категории, методики, версии правил, источники, исправления | Чтение через KB Gateway; запись только из контролируемого ETL и админ-процесса
Scanner Engine | не хранит знания как главный источник | Получает список применимых approved правил, исполняет встроенные handler-ы
AI Analyzer | контекст по запросу, без прав на публикацию | Формирует объяснения с ссылками; нет доступа к прямому исполнению правил

Контракт KnowledgeProvider: get_applicable_rules, get_weakness, get_remediations, get_release.
Сканер не знает Cypher; доступ через сервисный слой. При недоступности графа — кеш либо сканирование помечается ограниченным.

ИИ использует знания только через read-only шлюз; не публикует и не исполняет правила.
