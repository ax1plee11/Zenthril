# Security Model — ограничения при активном тестировании и ИИ (раздел 10)

## Блокирующие ограничения
- Активное тестирование только после проверки контроля над доменом, заданного scope и отдельного согласия.
- Запрещены разрушительные изменения данных, нагрузочные ататы, эксплуатация для извлечения секретов, выход за пределы объекта.
- Только HTTPS/HTTP к разрешённым публичным целям; локальные, loopback, link-local, metadata и внутренние IP отклоняются.
- Повторная проверка DNS после резолвинга, редиректов и перед соединением (защита от DNS rebinding и SSRF).
- Лимиты: число запросов, параллелизм, глубина, длительность, backoff, отмена задачи.
- Доказательства с маскированием токенов, cookies, персональных данных; ограничен срок хранения.
- Отсутствие находок не равняется гарантии безопасности.

## Использование ИИ (GraphRAG)
- AI Analyzer читает опубликованный граф через API с ограничением разрешённых полей и источников.
- Текст из OWASP/CVE/WSTG и сайтов клиентов считается недоверенным; инструкции внутри игнорируются как команды.
- ИИ может объяснять и рекомендовать, но не менять статусы RuleRevision и не запускать handler без отдельного разрешённого workflow.
- Для каждого вывода возвращать source_url, rule_revision_key, kb_release_id; различать подтвержденные и предполагаемые оценки.
- Контрольные тесты: prompt injection из описания CVE, ложное доказательство, противоречивые источники, отсутствующий CWE.

## Контроль доступа к Neo4j
- Порты 7474/7687 только на 127.0.0.1; не публиковать вовне.
- Доступ из backend по Docker-сети; secrets через Docker secrets/систему секретов.
- Community Edition: нет Enterprise-only online backup и тонкого встроенного RBAC; границы доступа обеспечивают API и сеть.
